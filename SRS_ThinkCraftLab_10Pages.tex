\section{Introduction}

\subsection{Purpose}
ThinkCraft Lab is a comprehensive full-stack web application combining e-commerce functionality for 3D printing products with an integrated events management system for students and makers. The platform provides a seamless marketplace for browsing and purchasing 3D printed products, accessing design services, and engaging with a community through workshops, competitions, and courses. It enables efficient order management, real-time event registration, and comprehensive user profile management in a secure environment.

\subsection{Intended Audience}
This document is intended for full-stack developers (React/Node.js), project managers, QA teams, business stakeholders, and end users including customers, students, event creators, and administrators.

\subsection{Project Scope}
ThinkCraft Lab creates an integrated ecosystem with two major components:

\textbf{E-commerce Platform:} The system provides a complete online shopping experience with a catalog of 50+ 3D printed products across three categories (3D Printing, Design Services, Prototyping). Users can browse products with pagination and filtering, add items to shopping cart with size and quantity selection, maintain a wishlist, apply discount coupons (10-25\% off), complete secure checkout with multiple payment options, and track order history with real-time status updates.

\textbf{Events Management System:} The platform enables community engagement through event creation and management. Users can create workshops, competitions, and courses with detailed information including title, description, category, images, date, location, and live status indicators. The system supports event registration with one-click sign-up, prevents duplicate registrations, tracks attendance, and provides comprehensive registration management for event creators and administrators.

\textbf{User Management:} The system supports four distinct user roles with hierarchical permissions. Guest users can browse products and events. Registered customers can make purchases, register for events, and manage profiles. Event creators have additional capabilities to create and manage their own events. Administrators have full system access including platform statistics, user management, and content moderation.

\section{Overall Description}

\subsection{Product Perspective}
ThinkCraft Lab operates as a standalone web application following modern client-server architecture. The frontend is built as a React-based single-page application (SPA) using TypeScript for type safety, Vite as the build tool, Tailwind CSS for styling, and Framer Motion with GSAP for advanced animations. The backend consists of a Node.js server running Express.js framework, implementing RESTful API architecture with session-based authentication. Data persistence is handled by MongoDB, a NoSQL document database, accessed through Mongoose ODM for object modeling and schema validation.

The deployment architecture leverages cloud services: Vercel hosts the frontend with CDN distribution for optimal performance, Render provides containerized backend hosting with auto-scaling capabilities, and MongoDB Atlas offers managed database hosting with replica sets and automatic backups. All communications are encrypted using HTTPS with secure cookie management for session handling.

\subsection{Product Functions}
The system provides comprehensive functionality across multiple domains:

\textbf{Authentication and Authorization:} Users can register with username, email, and password (minimum 6 characters). Passwords are securely hashed using bcrypt with 10 salt rounds. The system implements session-based authentication with 7-day persistence, allowing users to remain logged in across browser sessions. Role-based access control ensures users can only access features appropriate to their role. Profile management allows users to update personal information and change passwords with current password verification.

\textbf{Product Catalog and Shopping:} The catalog displays 50+ products with high-quality images, detailed descriptions, and pricing. Products are organized into three categories with filtering and pagination (9 products per page). Each product detail page shows specifications, size options (Small, Medium, Large, X-Large), quantity selection, and related products. The shopping cart maintains items with selected sizes and quantities, persists data in localStorage, calculates totals in real-time, and allows quantity updates or item removal. The wishlist feature enables users to save favorite products for later purchase.

\textbf{Checkout and Order Management:} The checkout process collects shipping information (address, city, state, zip, country) and offers multiple payment methods (Credit Card, PayPal, Cash on Delivery). A coupon system validates discount codes (FIRST10 for 10\% off, SAVE15 for 15\% off, MEGA25 for 25\% off, TEST10 for 10\% off) and applies discounts to order totals. Upon successful order placement, the system generates unique order numbers, stores complete order details, clears the shopping cart, and displays order confirmation. Users can view order history with status tracking (pending, processing, shipped, delivered) and access detailed order information including items, quantities, prices, and shipping details.

\textbf{Events Management:} Authenticated users can create events by providing title, description, category (Workshop, Competition, Course, Other), optional images, date and time, location, and live status indicator. The events discovery interface displays all events chronologically with filtering by category and separate views for live events. Each event shows creator information, registration count, and detailed description. The registration system allows one-click sign-up, prevents duplicate registrations, enables unregistration, and tracks all registrants with usernames and registration timestamps. Event creators can edit their events, delete them, and view complete registration lists. Administrators can manage all events regardless of creator.

\textbf{User Profile and Settings:} User profiles display personal information, complete order history with order numbers and totals, event registration history, account creation date, and admin status if applicable. The settings page allows username and email updates with uniqueness validation, password changes requiring current password verification, and notification preferences for email updates and order notifications. An integrated FAQ section provides answers to common questions about orders, returns, shipping, and account management.

\textbf{Administrative Functions:} The admin dashboard provides platform-wide statistics including total users, total events, total registrations across all events, and count of currently live events. Administrators can view all events in a comprehensive table with event details, creator information, registration counts, and status indicators. They can view detailed registration lists for any event and delete any event when necessary. The system restricts admin dashboard access to users with admin privileges verified through database flags.

\subsection{User Classes and Characteristics}
\textbf{Guest Users} represent visitors without accounts who can browse the product catalog, view product details, explore events, and access public pages (Home, About, Work). They must register to make purchases or register for events.

\textbf{Registered Customers} have all guest capabilities plus the ability to add products to cart and wishlist, complete purchases with saved shipping information, track orders with real-time status updates, register for events, manage their profile and settings, and view complete order and event history.

\textbf{Event Creators} possess all customer capabilities with additional permissions to create new events with full details, edit their own events, delete their own events, view registration lists for their events, and manage event live status.

\textbf{Administrators} have complete system access including all customer and creator capabilities, plus access to the admin dashboard, ability to view platform-wide statistics, manage all events regardless of creator, delete any event, view all event registrations, and manage user roles through database scripts.

\subsection{Operating Environment}
\textbf{Client-Side Requirements:} The application supports modern web browsers including Chrome 90+, Firefox 88+, Safari 14+, and Edge 90+. It operates on Windows 10+, macOS 10.15+, and Linux (Ubuntu 20.04+). The responsive design adapts to screen resolutions from 320px (mobile) to 2560px (large desktop). A broadband internet connection is recommended for optimal performance.

\textbf{Server-Side Requirements:} The backend requires Node.js version 18.x or higher, MongoDB 5.0 or higher, minimum 512MB RAM, and at least 1GB available storage space.

\textbf{Production Environment:} Frontend hosting on Vercel provides CDN-enabled static file serving with automatic HTTPS. Backend hosting on Render offers containerized deployment with auto-scaling. Database hosting on MongoDB Atlas includes replica sets for high availability, automatic backups, and point-in-time recovery.

\subsection{Design and Implementation Constraints}
\textbf{Technology Constraints:} The system must use React 18+ for frontend development, Node.js and Express.js for backend, MongoDB for data persistence, and TypeScript throughout for type safety.

\textbf{Security Constraints:} All passwords must be hashed using bcrypt with minimum 10 salt rounds. Session-based authentication is required with secure cookie handling. HTTPS must be enforced in production environments. CORS policies must be properly configured to allow only authorized origins.

\textbf{Performance Constraints:} Page load time must not exceed 3 seconds on broadband connections. API response time must be under 500ms for 95\% of requests. The system must support 100+ concurrent users. Database queries must be optimized with appropriate indexes.

\section{Database Design}

\subsection{Database Schema}
The system uses MongoDB with three main collections:

\textbf{Users Collection:} Stores user account information with fields: \_id (ObjectId, primary key), username (String, unique, required), email (String, unique, required), password (String, hashed with bcrypt, required), isAdmin (Boolean, default false), and createdAt (Date, default current timestamp). Indexes are created on username and email for fast lookup and uniqueness enforcement.

\textbf{Orders Collection:} Stores order information with fields: \_id (ObjectId, primary key), userId (String, indexed, required, references Users), orderNumber (String, unique, required), status (String, default 'pending'), subtotal (Number, required), discount (Number, default 0), couponCode (String, optional), totalAmount (Number, required), shippingAddress (String, required), shippingCity (String, required), shippingState (String, required), shippingZip (String, required), shippingCountry (String, default 'USA'), paymentMethod (String, required), items (Array of embedded documents containing productId, productName, productPrice, productImage, size, quantity), and createdAt (Date, default current timestamp). Indexes are created on userId for user order queries, orderNumber for unique lookup, and createdAt for chronological sorting.

\textbf{Events Collection:} Stores event information with fields: \_id (ObjectId, primary key), title (String, required), description (String, required), category (String, enum: workshop/competition/course/other, required), images (Array of Strings), date (Date, required), location (String, required), isLive (Boolean, default false), createdBy (ObjectId, references Users, required), createdByUsername (String, required), registrations (Array of embedded documents containing userId, username, registeredAt), createdAt (Date, auto-generated), and updatedAt (Date, auto-generated). Indexes are created on category for filtering, isLive for live event queries, date for chronological sorting, and createdBy for creator's event queries.

\subsection{Data Relationships}
Users to Orders: One-to-Many relationship where one user can have multiple orders. Orders reference users via userId field. Orders are retained for record-keeping even if user is deleted.

Users to Events (Creator): One-to-Many relationship where one user can create multiple events. Events reference creator via createdBy field.

Users to Events (Registrations): Many-to-Many relationship where users can register for multiple events and events can have multiple registrants. Registrations are embedded in events document as an array.

\subsection{Data Integrity}
The system enforces data integrity through Mongoose schema validation, unique indexes on username and email, required field validation, enum validation for category fields, and referential integrity through ObjectId references. All database operations use transactions where appropriate to ensure atomicity.

\section{System Architecture}

\subsection{Three-Tier Architecture}
\textbf{Presentation Layer:} The frontend is built as a React 18 single-page application using TypeScript for type safety. Vite serves as the build tool providing fast development server and optimized production builds. Tailwind CSS provides utility-first styling with custom theme configuration. Wouter handles client-side routing with minimal bundle size. TanStack Query manages server state with caching and automatic refetching. Framer Motion and GSAP provide smooth animations and transitions. The application is fully responsive, adapting to screen sizes from 320px to 2560px.

\textbf{Application Layer:} The backend runs on Node.js with Express.js framework implementing RESTful API architecture. Session-based authentication uses express-session with secure cookie configuration. Business logic is organized into route handlers, storage layer for database operations, and middleware for cross-cutting concerns. Input validation occurs at both route level and database schema level. Error handling middleware catches and formats all errors consistently. CORS middleware allows requests only from authorized frontend origins.

\textbf{Data Layer:} MongoDB provides document-based data storage with flexible schema. Mongoose ODM handles object modeling, schema validation, and query building. Collections are indexed for optimal query performance. Connection pooling manages database connections efficiently. Replica sets provide high availability and automatic failover.

\subsection{Component Architecture}
\textbf{Frontend Components:} Pages include Home (hero section, animations), Shop (product grid, pagination), Work (portfolio, 3D viewer), About (company info), Students (events hub), Profile (user dashboard), Admin (statistics, management), Cart, Wishlist, Checkout, and Order Confirmation. Layouts include Navigation (responsive menu, cart/wishlist badges) and Footer (links, contact info). Feature components include Cart management, Wishlist management, Checkout flow, and Events management. Context providers include AuthContext (user state, auth functions) and ShopContext (cart, wishlist state).

\textbf{Backend Modules:} Routes handle API endpoints for Auth (signup, login, logout, me), Orders (create, list, details), Events (CRUD operations, registration), Users (profile, password), and Admin (statistics). Models define Mongoose schemas for User, Order, and Event. Storage layer abstracts database operations providing clean interface for routes. Middleware includes authentication verification, CORS configuration, error handling, and request logging.

\subsection{Deployment Architecture}
\textbf{Production Setup:} Frontend is deployed on Vercel with automatic builds from GitHub, CDN distribution for static assets, automatic HTTPS, and environment variable configuration for API URL. Backend is deployed on Render with containerized deployment, automatic scaling based on load, health checks and automatic restarts, and environment variables for database connection and secrets. Database is hosted on MongoDB Atlas with M0 free tier (512MB storage), replica sets for high availability, automatic backups with point-in-time recovery, and network access configured to allow Render IP addresses.

\section{API Endpoints}

\subsection{Authentication Endpoints}
POST /api/auth/signup - Register new user with username, email, password. Returns user object with session.

POST /api/auth/login - Authenticate user with username and password. Returns user object with session.

POST /api/auth/logout - End user session. Returns success message.

GET /api/auth/me - Get current authenticated user information. Returns user object or 401 if not authenticated.

\subsection{Order Endpoints}
POST /api/orders - Create new order with shipping info, payment method, coupon code, and cart items. Requires authentication. Returns order object with unique order number.

GET /api/orders - Get all orders for authenticated user. Returns array of order objects sorted by date.

GET /api/orders/:orderId - Get specific order details. Requires authentication and order ownership. Returns order object with items array.

\subsection{Event Endpoints}
GET /api/events - Get all events. Optional query parameters: category (filter by category), live (filter live events). Returns array of event objects.

POST /api/events - Create new event. Requires authentication. Request body includes title, description, category, images, date, location, isLive. Returns created event object.

GET /api/events/:eventId - Get specific event details. Returns event object with registrations array.

PUT /api/events/:eventId - Update event. Requires authentication and creator ownership. Request body includes fields to update. Returns updated event object.

DELETE /api/events/:eventId - Delete event. Requires authentication and creator ownership or admin role. Returns success message.

POST /api/events/:eventId/register - Register for event. Requires authentication. Prevents duplicate registrations. Returns updated event object.

DELETE /api/events/:eventId/register - Unregister from event. Requires authentication. Returns updated event object.

\subsection{User and Admin Endpoints}
PUT /api/user/profile - Update user profile (username, email). Requires authentication. Validates uniqueness. Returns updated user object.

PUT /api/user/password - Change password. Requires authentication and current password. Validates new password length. Returns success message.

GET /api/admin/stats - Get platform statistics (total users, events, registrations, live events). Requires admin role. Returns statistics object.

\section{Deployment and Maintenance}

\subsection{Deployment Process}
Frontend Deployment on Vercel: Push code to GitHub repository. Connect repository to Vercel. Configure build settings with build command 'npm run build' and output directory 'dist/public'. Set environment variable VITE\_API\_URL to backend URL. Deploy and verify functionality.

Backend Deployment on Render: Push code to GitHub repository. Create new Web Service on Render. Configure service with build command 'npm install' and start command 'npm start'. Set environment variables: MONGODB\_URI (database connection string), SESSION\_SECRET (random secret key), NODE\_ENV (production), FRONTEND\_URL (Vercel URL for CORS). Deploy and verify API endpoints.

Database Setup on MongoDB Atlas: Create MongoDB Atlas account. Create new cluster (M0 Free tier). Configure network access to allow all IPs (0.0.0.0/0) for Render. Create database user with password. Get connection string. Configure in backend environment variables.

Database Maintenance: Monitor database size and performance metrics. Optimize slow queries using explain plans. Archive old orders (older than 2 years) to separate collection. Maintain indexes and rebuild if necessary. Regular backups with point-in-time recovery enabled.

Code Maintenance: Refactor code for better maintainability and performance. Update documentation when features change. Remove deprecated features and clean up unused code. Optimize bundle size by analyzing and removing unused dependencies. Update TypeScript types as schema evolves.

\subsection{Monitoring and Logging}
Application Monitoring: Monitor API response times and track error rates. Monitor user activity and track conversion rates. Set up alerts for critical errors.

Infrastructure Monitoring: Monitor server uptime and resource utilization. Track database performance metrics. Monitor CDN performance and cache hit rates.

Logging Strategy: Log all API requests with timestamps. Log authentication events (login, logout, failed attempts). Log errors with stack traces. Log database operations for audit trail. Implement log rotation to manage storage.
