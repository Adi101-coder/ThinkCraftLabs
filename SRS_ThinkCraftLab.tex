\chapter{Introduction}

\section{Purpose}
ThinkCraft Lab is a comprehensive web-based platform that combines e-commerce functionality for 3D printing products and services with an integrated events management system for students and makers. The platform addresses the growing need for accessible 3D printing solutions while fostering a community through workshops, competitions, and educational courses.

The main objectives of ThinkCraft Lab are:
\begin{itemize}
\item Provide an online marketplace for 3D printed products and design services
\item Enable seamless order management and tracking
\item Facilitate event creation and registration for educational activities
\item Support student engagement through workshops and competitions
\item Maintain comprehensive user profiles with order history and event participation
\end{itemize}

\section{Project Scope}
ThinkCraft Lab creates an integrated ecosystem for 3D printing enthusiasts, students, and professionals. The platform consists of two major components:

\subsection{E-commerce Platform}
\begin{itemize}
\item Product catalog with 50+ 3D printed items across multiple categories
\item Shopping cart with size selection and quantity management
\item Wishlist functionality for saving favorite products
\item Secure checkout process with multiple payment options
\item Order tracking and history
\item Coupon and discount system
\item User profile management
\end{itemize}

\subsection{Events Management System}
\begin{itemize}
\item Event creation for workshops, competitions, and courses
\item Event registration and attendance tracking
\item Live event indicators
\item Category-based event filtering
\item Event creator dashboard
\item Registration management
\end{itemize}

\subsection{User Roles}
The platform supports four distinct user roles:
\begin{itemize}
\item \textbf{Customers}: Browse products, make purchases, register for events
\item \textbf{Students}: Access educational content, participate in events
\item \textbf{Event Creators}: Create and manage workshops and competitions

\chapter{Overall Description}

\section{Product Perspective}
ThinkCraft Lab is a standalone web application that operates independently while integrating with external services for payment processing and cloud storage. The system architecture follows a modern client-server model:

\begin{itemize}
\item \textbf{Frontend}: React-based single-page application (SPA)
\item \textbf{Backend}: Node.js with Express.js REST API
\item \textbf{Database}: MongoDB for data persistence
\item \textbf{Deployment}: Vercel (frontend) and Render (backend)
\end{itemize}

The platform replaces traditional manual processes for:
\begin{itemize}
\item Product ordering and inventory management
\item Event registration and attendance tracking
\item Customer relationship management
\item Order fulfillment and tracking
\end{itemize}

\chapter{Database Design}

\section{Database Schema}

\subsection{Users Collection}
\begin{lstlisting}[language=JavaScript]
{
  _id: ObjectId,
  username: String (unique, required),
  email: String (unique, required),
  password: String (hashed, required),
  isAdmin: Boolean (default: false),
  createdAt: Date (default: now)
}
\end{lstlisting}

\subsection{Orders Collection}
\begin{lstlisting}[language=JavaScript]
{
  _id: ObjectId,
  userId: String (indexed, required),
  orderNumber: String (unique, required),
  status: String (default: 'pending'),
  subtotal: Number (required),
  discount: Number (default: 0),
  couponCode: String (optional),
  totalAmount: Number (required),
  shippingAddress: String (required),
  shippingCity: String (required),
  shippingState: String (required),
  shippingZip: String (required),
  shippingCountry: String (default: 'USA'),
  paymentMethod: String (required),
  items: [
    {
      productId: Number,
      productName: String,
      productPrice: Number,
      productImage: String,
      size: String,
      quantity: Number
    }
  ],
  createdAt: Date (default: now)
}
\end{lstlisting}

\subsection{Events Collection}
\begin{lstlisting}[language=JavaScript]
{
  _id: ObjectId,
  title: String (required),
  description: String (required),
  category: String (enum: workshop, competition, 
                    course, other),
  images: [String],
  date: Date (required),
  location: String (required),
  isLive: Boolean (default: false),
  createdBy: ObjectId (ref: User),
  createdByUsername: String (required),
  registrations: [
    {
      userId: ObjectId (ref: User),
      username: String,
      registeredAt: Date (default: now)
    }
  ],
  createdAt: Date,
  updatedAt: Date
}
\end{lstlisting}

\section{Data Relationships}

\subsection{User-Order Relationship}
\begin{itemize}
\item One user can have multiple orders (One-to-Many)
\item Orders reference users via userId field
\item Cascade delete: When user is deleted, their orders remain for record-keeping
\end{itemize}

\subsection{User-Event Relationship}
\begin{itemize}
\item One user can create multiple events (One-to-Many)
\item One user can register for multiple events (Many-to-Many)
\item Events reference creator via createdBy field
\item Registrations are embedded in events document
\end{itemize}

\section{Indexing Strategy}

\subsection{Users Collection Indexes}
\begin{itemize}
\item username: Unique index for fast lookup
\item email: Unique index for authentication
\end{itemize}

\subsection{Orders Collection Indexes}
\begin{itemize}
\item userId: Index for user order history queries
\item orderNumber: Unique index for order lookup
\item createdAt: Index for sorting by date
\end{itemize}

\subsection{Events Collection Indexes}
\begin{itemize}
\item category: Index for category filtering
\item isLive: Index for live events queries
\item date: Index for chronological sorting
\item createdBy: Index for creator's events
\end{itemize}

\subsection{Presentation Layer (Frontend)}
\begin{itemize}
\item React-based single-page application

\item Client-side routing with Wouter
\item State management with React Context and TanStack Query
\item Animations with Framer Motion and GSAP
\end{itemize}

\subsection{Application Layer (Backend)}
\begin{itemize}
\item Express.js REST API
\item Session-based authentication
\item Business logic implementation
\item Data validation and sanitization
\item Error handling and logging
\end{itemize}

\subsection{Data Layer (Database)}
\begin{itemize}
\item MongoDB for data persistence
\item Mongoose for object modeling
\item Indexed collections for performance
\item Data validation at schema level
\end{itemize}
