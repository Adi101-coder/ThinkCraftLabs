\section{Introduction}

\subsection{Purpose}
ThinkCraft Lab is a full-stack web platform combining 3D printing e-commerce with events management for students and makers. It enables product browsing/purchasing, order tracking, and community engagement through workshops, competitions, and courses.

\subsection{Scope}
\textbf{E-commerce}: 50+ products, cart, wishlist, checkout with coupons (10-25\% off), order management\\
\textbf{Events}: Create/manage workshops/competitions/courses, registration tracking, live event indicators\\
\textbf{Users}: Authentication, profiles, role-based access (Guest, Customer, Event Creator, Admin)\\
\textbf{Admin}: Dashboard with statistics, event/user management

\section{System Overview}

\subsection{Architecture}
\textbf{Frontend}: React 18 + TypeScript + Vite + Tailwind CSS + Framer Motion\\
\textbf{Backend}: Node.js + Express.js REST API + Session Auth\\
\textbf{Database}: MongoDB + Mongoose ODM\\
\textbf{Deployment}: Vercel (frontend), Render (backend), MongoDB Atlas

\subsection{User Roles}
\textbf{Guest}: Browse products/events, view public pages\\
\textbf{Customer}: Purchase, register for events, manage profile\\
\textbf{Event Creator}: Create/manage events, view registrations\\
\textbf{Admin}: Full access, analytics, manage all content

\subsection{Constraints}
Tech stack: React, Node.js, Express, MongoDB, TypeScript required. Session-based auth with bcrypt. HTTPS in production. Performance: Page load <3s, API <500ms, 100+ concurrent users.

\section{Functional Requirements}

\subsection{Authentication (Priority: High)}
\begin{itemize}
\item User registration: username, email, password (min 6 chars), bcrypt hashing
\item Secure login with 7-day session persistence
\item Profile management, password updates, role-based access control
\end{itemize}

\subsection{E-commerce (Priority: High)}
\textbf{Catalog}: 50+ products, 3 categories (3D Printing, Design Services, Prototyping), pagination (9/page), filtering\\
\textbf{Cart}: Add/remove items, size selection, quantity updates, persistent storage, total calculation\\
\textbf{Wishlist}: Save favorites, move to cart, prevent duplicates\\
\textbf{Checkout}: Shipping info, payment methods (Credit Card, PayPal, COD), coupon system\\
\textbf{Coupons}: FIRST10 (10\%), SAVE15 (15\%), MEGA25 (25\%), TEST10 (10\%)\\
\textbf{Orders}: Unique order numbers, status tracking (pending/processing/shipped/delivered), order history

\section{Database Design}

\subsection{Collections}
\textbf{Users}: \_id, username*, email*, password (hashed), isAdmin, createdAt (*unique)\\
\textbf{Orders}: \_id, userId, orderNumber*, status, subtotal, discount, couponCode, totalAmount, shipping (address, city, state, zip, country), paymentMethod, items[], createdAt\\
\textbf{Events}: \_id, title, description, category, images[], date, location, isLive, createdBy, createdByUsername, registrations[{userId, username, registeredAt}], timestamps

\subsection{Relationships}
Users (1)→(Many) Orders | Users (1)→(Many) Events (creator) | Users (Many)↔(Many) Events (registrations)

\subsection{Indexes}
Users: username, email | Orders: userId, orderNumber, createdAt | Events: category, isLive, date, createdBy

\section{Non-Functional Requirements}

\subsection{Performance}
Page load <3s, API <500ms (95\%), 100+ concurrent users, 1000+ req/min. Frontend bundle <2MB, backend memory <512MB. Optimized images, lazy loading, database indexes.

\subsection{Security}
Bcrypt hashing (10 rounds), session auth (7-day timeout), HTTPS, secure cookies. Input validation (client \& server), XSS/CSRF protection. Role-based access, environment variables for secrets.

\subsection{Reliability}
99\% uptime, graceful error handling, user-friendly messages, server logging. Database integrity, atomic transactions.

\subsection{Usability}
Registration <2min, purchase <5min. Responsive (320px-2560px), keyboard navigable, WCAG 2.1 AA contrast. Touch targets 44x44px on mobile.

\subsection{Maintainability}
TypeScript, modular code, inline comments, consistent naming. API/DB documentation, deployment guides. Unit/integration tests.

\section{API Endpoints}

\textbf{Auth}: POST /api/auth/signup, POST /api/auth/login, POST /api/auth/logout, GET /api/auth/me\\
\textbf{Orders}: POST /api/orders, GET /api/orders, GET /api/orders/:orderId\\
\textbf{Events}: GET /api/events, POST /api/events, GET /api/events/:eventId, PUT /api/events/:eventId, DELETE /api/events/:eventId, POST /api/events/:eventId/register, DELETE /api/events/:eventId/register\\
\textbf{User}: PUT /api/user/profile, PUT /api/user/password\\
\textbf{Admin}: GET /api/admin/stats

\section{Deployment \& Testing}

\subsection{Production Deployment}
\textbf{Vercel (Frontend)}: Build: npm run build, Output: dist/public, Env: VITE\_API\_URL\\
\textbf{Render (Backend)}: Build: npm install, Start: npm start, Env: MONGODB\_URI, SESSION\_SECRET, NODE\_ENV=production, FRONTEND\_URL\\
\textbf{MongoDB Atlas}: M0 Free (512MB), replica sets, network access: all IPs, auto backups

\subsection{Maintenance}
Monitor performance/uptime, review logs weekly. Update dependencies monthly, security patches promptly. DB backups weekly, archive old orders (2+ years).

\subsection{Testing Strategy}
\textbf{Unit}: Individual functions, mock dependencies, 70\%+ coverage\\
\textbf{Integration}: API endpoints, DB operations, auth flow\\
\textbf{E2E}: Complete workflows (shopping, checkout, events)\\
\textbf{Performance}: Load (100 users), stress testing\\
\textbf{Security}: SQL injection, XSS, CSRF, auth bypass

\textbf{Key Test Cases}: Auth (register, login, logout, password change), E-commerce (browse, cart, coupon, checkout, orders), Events (create, edit, delete, register), Admin (dashboard, stats, management)
